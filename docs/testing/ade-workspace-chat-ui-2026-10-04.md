## Implemented behavior

- `App.tsx` no longer mounts the global EmbeddedAgentWidget. Settings and sidebar use Agents; the embedded API-key/model configuration form is removed from SettingsPage. Existing stored credentials are not deleted or migrated.
- `WorkspaceLayout` makes chat the main project surface beside files/terminals, with a tool-pane toggle. Existing split/tab layout and Kanban remain available. Global context displays project onboarding; mounted open-project chats retain drafts through project/global navigation and section changes.
- Each mounted chat is keyed to backend credentials/origin and project. Conversation drafts are separate; histories come from the selected project's backend routes. Backend changes remount the chat. Drafts are transient and are not promised to survive closing a project or restarting the app.
- Loading a workspace issues reads only. Starting a conversation requires an explicit click and creates metadata, not a provider process. Sending starts an async CLI turn; the UI distinguishes accepted messages and in-progress turns from completed responses. No mutation is automatically retried.
- Failed send keeps the prompt and reports uncertainty. Poll failures recheck observations every five seconds without resending and block new sends until observations recover. Responses for another project/session are rejected, including stop responses. Enter sends, Shift+Enter adds a line, and IME composition does not submit.
- Stop cancels only the owned chat turn. It never calls task stop/reset or removes a worktree/branch. Providers come from backend configuration/capability checks; configured does not prove login. Model is shown as unobserved. Transcript replay is explicit rather than described as provider-native resume.
- Updated and synchronized the Orchestra CLI skill's task contract: task-orchestrator `status` does not include workspace-chat turns, and chat conversation IDs cannot substitute for task IDs. No new CLI commands are advertised.
