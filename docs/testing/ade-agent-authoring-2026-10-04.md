# Native agent and skill authoring implementation

The source/behavior comparison is recorded in `docs/superpowers/plans/ade-2026-10-03/opencode-agent-mode-integration.md`: OpenCode revision `907b3bc518fa48e90e8ec24dd327d13eee71c36c`, Orca `3284b4c70c901402831bb4ccc5576ea083d2e5ae`, and T3 Code `737993303d36e10674c54b95e5bd3826682c99c7`. OpenCode's legacy agent documentation establishes Tab cycling; its V2 documentation has a different native agent format and is not evidence that legacy runtime flags work. Orca's configuration precedence/observed-versus-requested distinction and T3's composer-local controls are adapted to Orchestra's harness-owned definitions. Neither pinned Orca nor T3 source inspected here supplies a directly interchangeable OpenCode named-agent selector.

The composer displays a harness-scoped agent picker, including Maestro's global `__orchestrator__` scope. Only catalog rows explicitly selectable as primary under a verified capability can be chosen/cycled. Tab cycles forward and Shift+Tab backward from the message input or selector, preserving input focus; ordinary keyboard navigation remains when no selectable modes exist. Unsupported/subagent-only resources cannot silently become primary modes. Agent ID, scope, native format and content hash are separate from model/effort and captured in creation/submission arguments and draft recovery metadata. Existing saved session intent is shown; requested intent is not claimed as effective provider behavior.

The Agents tab's Claude/Codex/OpenCode agent and skill editors use the same catalog endpoints as the native `orchestra_resources` control and CLI wrappers. The editor saves raw documents with optimistic content hashes, preserves unknown metadata, and requires explicit deletion confirmation. Receipts are retained in profile storage under a credential-digested scope before dispatch; unresolved outcomes block further edits and are checked without replay. Global authoring uses global-only Maestro scope. Project authoring uses the selected checkout ID; no alternate-root fallback is introduced. Other harnesses retain their existing panels until a safe authoring adapter exists.

OpenCode's legacy mode editor also uses Orchestra's styled dropdown, rejects invalid modes, and preserves nested YAML permissions/unknown keys and no-op bytes using the YAML document parser. No runtime global model or provider account default is rewritten.
