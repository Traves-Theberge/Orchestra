## Orchestra adaptation

New `internal/agents/native_session.go` defines a native capability boundary separate from batch runners. Registry advertises native sessions only for configured native Codex commands and rejects remote sessions and unsupported turn budgets. `codex_native.go` owns one child process and one provider thread. Initialization occurs once, later messages use `turn/start` on the same thread, and saved thread IDs use `thread/resume`. Resume mismatch fails rather than starting a new conversation silently.

Native command selection is independent of batch task execution. Config loads `NativeAgentCommands["CODEX"]` as `codex app-server`; `ORCHESTRA_NATIVE_COMMAND_CODEX` overrides it, and an explicitly empty variable disables native chat. Startup applies this map to the registry. Registry constructors also select the safe native default when Codex is configured; neither batch command templates nor batch approval-bypass flags are inherited. Explicit native overrides remain stable across subsequent batch command changes. Custom protocol fixtures use `SetNativeCommand` rather than smuggling their command through a batch setting.

The reader dispatches RPC responses independently of turn callbacks, allowing interactive responses and interruption while a turn streams. Thread/turn identities fence notifications and requests. Invalid and duplicate answers are rejected. Explicit interruption keeps the process/thread reusable; cancellation, malformed protocol, uncertain dispatch, EOF and startup failures close/reap the process. Orchestra sends no configuration-write RPC or automatic approval response; sandbox/approval settings are inherited and returned provider settings are exposed separately from requested model selection. The provider can automatically persist project trust inside its selected CODEX_HOME; the writable coding canary detected a Codex config mutation. See the [provider trust diagnostic](ade-codex-provider-trust-diagnostic-2026-10-04.md).

Typed events preserve raw provider payloads for tools, progress, requests and usage. Token usage reports provider-observed last-turn and thread-total input/output/cache-read/cache-write/reasoning counters plus context window; no dollar cost is inferred. Optional `NativeModelCatalogProvider.ListModels` reads the provider catalog; catalog presence does not establish account entitlement. Changing the model for a turn clears an earlier observed model rather than relabeling requested intent as observed execution.

`Registry.NativeModels` provides pre-conversation catalog discovery through a separate initialized app-server process. It validates the authorized workspace first, requests `model/list` without `thread/start`, `thread/resume` or inference, follows bounded pagination, returns typed model IDs/names/default and reasoning/input metadata, and closes/reaps the process on every return path. EOF, malformed catalog identity/data, repeated cursors, excess pages and timeout are errors, never substituted hardcoded models. The installed 0.160.0 `ModelListParams` and `ModelListResponse` schemas were inspected for this follow-up.

Reasoning selection uses optional `NativeTurnOptionsSession.SendTurnWithOptions`, retaining the original `SendTurn` as a model-only wrapper. Installed `TurnStartParams` declares the wire field `effort`, an advertised nonempty string that overrides the current and subsequent turns. Empty Orchestra effort omits that field and inherits the thread's current setting; it does not promise to reset a previous override. Adapter validation bounds the identifier before any turn RPC. Workspace service validation checks exact advertised model support. `thread/start` and `thread/resume` report observed `reasoningEffort`; changed turn effort clears that earlier observation because the turn response has no effective-effort field. Requested effort is never substituted as observed effort.

Deliberate differences: one native thread per Orchestra session, no multi-thread process pool or Effect runtime; durable delivery receipts and UI projection belong to the workspace chat service. Command/file approval decisions and structured user questions are supported. Permission grants, arbitrary dynamic tool calls, authentication handshakes, attachments, steering, compaction and fork/rollback are not implemented here; unsupported server requests fail closed. Claude/OpenCode are not relabeled as native-capable. Existing batch Codex behavior is unchanged.

## Behavioral verification

### Persistent observation after turn settlement

Follow-up source inspection covered pinned T3 `ProviderSessionManager.ts` (session event pump independent of per-run subscribers), `ProjectionStore.ts:559` and `ProviderTurnTokenUsage.test.ts` (terminal updates preserve already observed usage). Pinned Orca `agent-session-wire/provider-frame-disposition.ts` and tests classify token usage and thread status separately from timeline/turn activity; `structured-agent-session-conversation-lifetime.ts` keeps conversation residency distinct from turn delivery and coordinates idle teardown. Orchestra borrows session-owned observation and explicit event attribution rather than terminating the subscription at `turn/completed`.

The native adapter now has a persistent protocol-event pump, an independent serialized callback dispatcher, and a separate active-turn await channel. Late usage/status for the same thread and a known completed turn remains observable while idle; foreign-thread and unknown-turn frames are rejected. Historical native turn IDs returned by resume are included; the in-memory known-turn horizon is bounded to the latest 256 IDs. No callback is duplicated between the pump and turn await loop. RPC response waits are bounded and independent of observer callbacks. Bounded queues apply backpressure rather than failing merely because an idle session produced more than 256 frames.

Callbacks are asynchronous relative to `SendTurn` returning. `Close` reaps the provider without waiting on a callback that may itself be issuing a turn/RPC. Owners must then call optional `DrainEvents` outside callbacks before tearing down callback dependencies such as SQLite. After close, this is a true dispatcher-completion barrier: the pump waits for protocol reader exit, drains already-read frames, closes the callback queue, and the dispatcher finishes before the barrier returns. Frames still unread in the OS pipe when the process is forcibly killed cannot be acknowledged; this does not promise delivery of future provider events after close.

The fixture suite verifies usage arriving after completion without another turn, 600 idle status frames with a healthy subsequent RPC, foreign/stale fences, an idle observer issuing a catalog RPC and another turn without deadlock, and close/drain joining a deliberately blocked callback while retaining an already-read late usage frame. Current-source focused Docker race checks across agents/workspacechat passed (`4.077s` / `3.805s`). No account-connected canary was launched for this follow-up.

`codex_native_test.go` launches a separate fixture process over actual OS stdin/stdout. It verifies two turns in one process/thread, saved-thread resume, resume mismatch rejection, stale completion suppression, command approval and question responses, malformed and duplicate answer rejection, nondestructive interruption followed by another turn, initialization EOF, active-turn EOF, cancellation and prompt process cleanup. The fixture never invokes an inference provider or writes account settings.

`codex_native_models_test.go` records the catalog-only process protocol methods and verifies exactly initialization and paginated model listing, with no thread/turn methods. It checks typed reasoning/default metadata, EOF/malformed/repeated-cursor failure cleanup and workspace validation before child startup.

`codex_native_options_test.go` records actual `turn/start` payloads, verifies explicit effort serialization and default omission, rejects malformed effort before a turn write, and checks observed thread effort versus unknown effective effort after an override.
