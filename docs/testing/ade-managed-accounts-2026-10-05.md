## Orchestra adaptation and verification boundary

- [`harnessaccounts/store.go`](../../apps/backend/internal/harnessaccounts/store.go) stores opaque account metadata and versioned selection under a backend-host private short path. Each Codex account receives a distinct credential home. The host default remains a separate context. Short homes avoid a macOS Unix-socket path problem reported in [Orca #18566](https://github.com/stablyai/orca/issues/18566). No token or credential path is returned by the API.
- [`harness_accounts.go`](../../apps/backend/internal/api/harness_accounts.go) exposes protected add, verify, reauth, select, list, and remove routes. Device login runs in the chosen home; success is followed by `codex login status` against that same home. Stale selections conflict. Removal refuses selected accounts, running/retrying task bindings, active conversation turns, and in-process leases. Idle native sessions are closed, historical transcripts retain their binding, and a new send on a removed binding fails before acceptance. Provider revocation is not available through this flow; deletion removes only the owned home.
- [`registry.go`](../../apps/backend/internal/agents/registry.go), [`state.go`](../../apps/backend/internal/orchestrator/state.go), and [`service.go`](../../apps/backend/internal/workspacechat/service.go) bind the active Codex account to a newly admitted task or conversation. Batch, native, model catalog, and structured app-server processes resolve the account home without global environment mutation. Restored runs and retries carry the binding. Remote managed-account execution fails closed.
- [`usage/service.go`](../../apps/backend/internal/usage/service.go) fetches Codex windows inside the selected home, tags them with account ID, label, and source, and invalidates cached windows on switch. The quick roster displays the selected account label. It lists Antigravity and 8gent with explicit unavailable quota/history states and keeps legacy Gemini history visible. Local log totals remain a separate source; they are not assigned to the selected account.
- [`HarnessSetupPanel.tsx`](../../apps/desktop/src/features/agents/panels/HarnessSetupPanel.tsx) provides Orchestra-styled account controls and distinguishes host-default sign-in from managed-account sign-in. OpenCode reports a saved credential entry count only when the documented JSON catalog parses; Antigravity and 8gent show explicit capability boundaries rather than fabricated signed-in states.

Tests cover two isolated homes, durable/stale selection, discarded abandoned sign-in, secret stripping, remote rejection, a conversation retaining account A after selection of B, historical conversation access and send rejection after removal, protected account routes, UI switch invalidation, and the existing device-login protocol. Tests and builds do not prove that two real ChatGPT accounts can sign in and keep independent refresh tokens, that a live model request succeeds, or that the provider's live quota response matches the selected account. [Orca #5370](https://github.com/stablyai/orca/issues/5370) specifically reports refresh-token contention when the same identity is used in host and isolated homes. We do not import/duplicate the host default automatically. Managed Claude is deferred because [Anthropic reports a macOS keychain collision](https://github.com/anthropics/claude-code/issues/20553) and [a Linux config-dir isolation failure](https://github.com/anthropics/claude-code/issues/47661); `CLAUDE_CONFIG_DIR` alone is insufficient evidence of safe multi-account isolation across supported platforms. Other harness accounts, full account-scoped historical usage, and real E2E auth/usage validation remain open.
