# Configuration boundary review

Read-only review of the integrated renderer and Studio → tracker → database → dispatch chain. No production files, databases, provider configuration, or task workspaces were changed for this review. This is input to [03 agent configuration](../superpowers/plans/ade-2026-10-03/03-agent-configuration.md), not completion evidence for that package.

The configuration chain is incomplete. Draft persistence exists, but selected model/turn limits are lost at Push. Other authoring fields are written to issue columns and then omitted from the task read model. Dispatch supplies hardcoded policies and does not expose a typed model/policy configuration to runners.

## Reference receipt

Both pinned references from the [registry](../superpowers/plans/ade-2026-10-03/reference-patterns.md) were considered:

Associated [ChatView.logic tests](https://github.com/pingdotgg/t3code/blob/737993303d36e10674c54b95e5bd3826682c99c7/apps/web/src/components/ChatView.logic.test.ts) check model-change restrictions and local-versus-server submission state.
- Orca `3284b4c70c901402831bb4ccc5576ea083d2e5ae`, [agent-project-model-override.ts](https://github.com/stablyai/orca/blob/3284b4c70c901402831bb4ccc5576ea083d2e5ae/src/main/native-chat/agent-model-catalog/agent-project-model-override.ts) and [tests](https://github.com/stablyai/orca/blob/3284b4c70c901402831bb4ccc5576ea083d2e5ae/src/main/native-chat/agent-model-catalog/agent-project-model-override.test.ts): model defaults depend on workspace-native configuration; finding a model override does not establish its effective value. [Dispatch observation tests](https://github.com/stablyai/orca/blob/3284b4c70c901402831bb4ccc5576ea083d2e5ae/src/main/native-chat/agent-session-journal/journal-dispatch-observation.test.ts) retain submission uncertainty and fence observations.

Proposed adaptation: typed requested configuration on the task; a versioned effective snapshot with provenance on each admitted run; provider capability validation before launch; recording-adapter verification of the actual launch input. Track provider observations separately and leave native defaults unknown when undiscoverable.

Deliberate differences: retain Go/SQLite orchestration ownership, existing Kanban columns and separate tracker identity. Hosted trackers require local execution metadata rather than assuming their fields support the whole configuration. No source copying is proposed. This review does not establish either reference's runtime behavior; neither reference application was run. The inspected Orca files do not define a directly equivalent Studio-to-SQLite Push flow, so the transaction/recovery design remains Orchestra-specific.

## Additional save/recovery hazards

- `internal/studio/manager.go:142` applies patch fields one at a time in map iteration order. String type assertions ignore failure (`:153`, `:158`); floats for max turns are truncated (`:165`); `SetMaxTurns` at `:369` accepts nonpositive values. Invalid multi-field patches can partly persist before returning an error. A nullable, bounded integer contract is needed.
- Clearing max turns sends `undefined` from `AgentGuidance.tsx:34`; `core/api/client.ts:2547` serializes the patch with JSON, which omits that field. Clearing the visible input therefore does not clear the stored limit. Define explicit null/inherit semantics.
- `useStudioSession.ts:123` changes local draft state before awaiting persistence, with no rollback or returned canonical draft. `draft/useDraft.ts:10` ignores session identity, retaining the old draft across a session switch until a new snapshot arrives. A late server snapshot can also overwrite a local edit without draft revision conflict handling.
- Desktop criteria and attachment edits send whole-field patches (`draft/fields/AcceptanceCriteria.tsx:16`, `Attachments.tsx:17`). The API manager only accepts the five scalar fields listed above and rejects other fields at `manager.go:175`. These visible edits therefore cannot currently persist through this REST patch path, even though the separate manager/MCP methods can mutate those lists.
- Push creates the issue before updating authoring metadata (`manager.go:221`, `:243`). An update failure leaves an issue and the still-existing draft; repeating Push creates another issue. Its mutex protects a single manager process only. The existing “idempotent” test (`manager_test.go:191`) asserts one successful caller and four failures; it does not verify repeated calls return the same receipt or crash recovery. Draft deletion/session ending errors are ignored (`manager.go:247`).
- Studio authoring model selection does not configure its attached runner: `spawner.go:104` builds a request from session/worktree/message only. The production spawner emits `chat.token` at `:115`, while renderer `useStudioSession.ts:95` handles `chat.message` and lacks a token/error branch. This adjacent native-chat gap needs its own explicit stream contract; lint passing did not fix it.

## Integrated renderer review

The lint patch retains task behavior; it does not repair the configuration chain above. Config editor keys now include path/content (`CodexEnvironmentPanel.tsx:19`, `GeminiContextPanel.tsx:24`), so refreshed source content or a file switch creates a fresh draft. This matches existing content-refresh reset semantics and additionally fixes same-content path switches. It deliberately does not preserve edits across a source revision; future conflict-aware draft handling should make that choice visible.

PR form remounting (`PRCreateDialog.tsx:20`) resets fields on opening or source identity changes. Browser URL resets and sidebar section resets are conditional and terminate after their source key changes. The Studio event factory effect updates the ref before the stream setup effect; it does not make the provider stream durable. JSON output has a real error boundary and Git diff effects reject callbacks after selection changes. The prior handoff records renderer regression evidence; no new runtime claim arises from this read-only review.

## Smallest executable next slices

1. **Make patch/save semantics truthful.** Add one typed draft patch validator, reject invalid or fractional/nonpositive limits before any write, permit explicit null/inherit, and apply multi-field changes atomically. Return a canonical revisioned snapshot. Surface save failure and prevent stale-session or stale-revision UI updates. Keep these tests in disposable SQLite and mocked renderer clients.
2. **Preserve requested task configuration.** Define the minimal versioned config object: canonical provider, optional model, optional Orchestra attempt budget, optional native turn budget and explicit inherit markers. Add a local task metadata DAO and extend WorkItem/list/detail/candidate SELECTs consistently. Store criteria/guidance/attachments alongside the config. Update Push to transfer every field; do not hide settings in untyped guidance alone.
3. **Give Push a durable receipt.** Add authoring-session → task association and recovery status before draft cleanup. SQLite-local create/metadata/receipt should be one transaction. Hosted create requires a persisted request identity and recovery for uncertain outcomes. Return the same task receipt on repeat; preserve resumable metadata-save failure instead of issuing another create.
4. **Freeze admission configuration.** Resolve explicit task values against documented project/application defaults, validate capabilities, and persist config ID/hash/provenance with run/attempt identity before launch. Invalid providers must fail visibly. Retry/revision explicitly retains or resolves a new snapshot; restart reloads it. Integrate with package 02 rather than extending the lossy running-row snapshot into an accidental second authority.
5. **Apply the frozen request at the adapter boundary.** Extend TurnRequest with typed model/effort/policy/limits and effective-config identity. Remove unconditional dispatch approval and hardcoded attempt count only after the alternative is wired end to end. Validate command template/native option conflicts. A recording runner verifies exact values; native observations distinguish confirmed values from unknown defaults. Antigravity remains a separate capability-gated adapter, not a Gemini alias.
6. **Materialize only approved workspace inputs.** Use a manifest of instruction/config/skill/MCP references and source hashes. Define tracked versus ignored/uncommitted discovery and collision policy. Never configure a task by mutating account/global directories. Missing or rejected required configuration prevents launch. This slice needs native discovery semantics and worktree lifecycle tests, so it should follow the resolver/receipt work.

## Required acceptance evidence

| Scenario | Independent assertion |
| --- | --- |
| Save/reload/restart | Selected provider/model/budgets and explicit null values survive canonical API reload and process restart. An invalid combined patch changes no field. |
| Push/read/dispatch | Real SQLite tracker round-trip returns equal requested configuration and criteria/guidance/attachments through detail/list/candidate paths, not merely fake tracker call arguments. |
| Partial Push failures | Inject failure before create, after create, during metadata persistence and during cleanup; repeated requests return one task and a durable receipt, with no hidden duplicate. |
| Admission freeze | Two tasks with conflicting model/policy values produce different correct recording-runner inputs. Changing project defaults while running does not mutate either snapshot. |
| Policy enforcement | Unsupported options/provider fail before spawn. A denied tool call is rejected at execution, not just absent from advertisements. Native permission/tool canaries are required per supported real adapter. |
| Workspace preparation | Disposable worktrees with tracked, ignored, uncommitted and colliding config produce the documented manifest or visible failure; global file hashes stay unchanged. |
| Retry/restart/revision | Effective config identity, workspace ownership, provider and restrictions survive recovery; revisions follow the documented retain/new-version policy. |
| Renderer save failures | Rejected save shows an error, reload shows the stored value, session switches cannot show the previous draft, and late snapshots cannot silently overwrite a newer saved edit. |
| Real Antigravity | Authenticated native canary reports the selected model/policies where available and proves cancellation, tool boundaries and concurrent task isolation. Recording fixtures alone cannot satisfy this row. |

No new tests or provider runs were executed for this read-only review. These scenarios are requirements for the implementation slices; none are marked passed here.
