# ADE harness settings and usage: living handoff

Status: Settings placement and persisted register/unregister flow implemented; focused tests pass. Update this file after each implementation or verification step. This is the entry point for another developer; detailed source receipts remain linked below.

## Goal and current decisions

The user wants Orca-like onboarding for **all registered harnesses** in Orchestra's main Settings, plus usage and quick insights in Orchestra's visual style. Keep the Kanban model and native provider chat. The five active harnesses are Codex, Claude Code, OpenCode, Antigravity, and 8gent. Gemini CLI appears only as legacy usage history. Show registration, installation, authentication evidence, and runtime capability separately; never equate a detected CLI or saved credential entry with verified access.

Managed account selection is implemented only for Codex. Each account has an isolated backend-owned `CODEX_HOME`; new task runs and conversations bind the selected account, existing conversations retain theirs, and Codex quota is attributed to the selected account. Claude, OpenCode, Antigravity, and 8gent use host CLI setup until safe account isolation can be verified. These are deliberate capability boundaries, not completed multi-account parity.

## Implemented code

- Backend managed accounts: `apps/backend/internal/harnessaccounts/`, `internal/api/harness_accounts.go`, `internal/harnesssetup/codex_device_login.go`, plus `internal/agents/registry.go`, `internal/orchestrator/state.go`, `internal/workspacechat/`, and `internal/usage/`. Protected API supports Codex add, verify, reauth, select, list, and remove. Idle historical conversations remain readable after removal but reject fresh messages.
- Existing Agent Hub: `apps/desktop/src/features/agents/panels/HarnessSetupPanel.tsx` lists all five harnesses, exposes provider-specific setup evidence and guidance, and shows managed Codex accounts. `apps/desktop/src/features/usage/UsageStatusBar.tsx` provides the quick usage roster. `UsagePage.tsx` shows detailed local history and provider quota.
- Main Settings placement: `SettingsPage.tsx` and `AppSidebar.tsx` now have Harnesses and Usage sections. The shared onboarding panel is rendered in Settings so behavior stays aligned with Agent Hub. The detailed Usage page is embedded without a duplicate page header. Quota tiles include all five harnesses plus legacy Gemini; separate history cards explicitly mark Antigravity and 8gent unavailable rather than implying a local scanner exists.
- Registration: `internal/agents/registry.go` overlays persisted availability on configured runners. `internal/db/db.go` creates `harness_registration`, `harness_command_overrides`, and `harness_default_selection`; `internal/orchestrator/state.go` restores them at startup, persists command/default edits, and applies versioned availability changes. `internal/app/run.go` reads the current default each dispatch tick, so changing it in Settings affects new task claims without a backend restart. `internal/api/harness_setup.go` exposes observed `registration_version` and protected `PUT /api/v1/agents/{provider}/registration` with `registered` and `expected_version`. The Settings/Agent Hub panel provides Register/Unregister for all five active harnesses, requires a configured command to register, and asks for a new default before unregistering the current one. Authentication and CLI installation are unchanged by registration.
