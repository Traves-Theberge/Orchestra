## Implemented behavior

- Code: [host probe](../../apps/backend/internal/harnesssetup/probe.go), [protected API handler](../../apps/backend/internal/api/harness_setup.go), [Agent Hub setup panel](../../apps/desktop/src/features/agents/panels/HarnessSetupPanel.tsx), and [quick-usage roster](../../apps/desktop/src/features/usage/UsageStatusBar.tsx).
- Protected `GET /api/v1/agents/setup` reports five active task harnesses: registered runner, configured batch command, executable discovery on backend PATH or from a configured absolute path, and authentication observation. It never executes a configured command template. Codex `login status` runs with a three-second deadline; its output is capped, inspected only for the exact signed-out response, and never sent to the UI. Other CLI errors remain unknown. This distinction follows [Codex's login-status implementation](https://github.com/openai/codex/blob/main/codex-rs/cli/src/login.rs), which uses exit code 1 for both signed-out and errors. Claude `auth status` is also read-only and [documented to emit JSON with an exit status](https://code.claude.com/docs/en/cli-reference); Orchestra accepts only consistent structured `loggedIn` and `authMethod` fields.
- Agent Hub shows those observations and provides provider setup documentation. On hosts with a working backend PTY and a detected CLI, `Open sign-in terminal` launches the provider command. On Windows, the backend's Unix PTY is unavailable, so the UI offers copy-and-run commands for a terminal on that backend host and never presents an unusable launch button. When Codex is detected, Orchestra can start its [structured app-server device-code flow](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md), show the one-time code and verification URL, poll the matching completion notification, and cancel the attempt. This is still a host-scoped single-account setup flow; a successful completion triggers a fresh read-only auth observation.
- The status bar has a consolidated usage roster with explicit unknown, unavailable, error, or reported quota states, refresh, and navigation to usage history. Opening it reads each supported provider's existing local 30-day token total on demand; Refresh updates local scans and quota windows. Claude and Codex retain detailed quota windows. Local totals and quota windows are labeled separately. The later [managed-account slice](./ade-managed-accounts-2026-10-05.md) adds selected Codex account attribution and visible Antigravity and 8gent unavailable states; legacy Gemini history remains visible.
- Gemini CLI remains a legacy local-log usage source, not a registered task harness; Antigravity remains the active Google task harness. No quota percentage is invented for Gemini or OpenCode.
- Provider credential-home and API environment variables now reach the matching sanitized batch process (`CODEX_HOME`, `OPENAI_API_KEY`, and `CODEX_ACCESS_TOKEN` for Codex; `CLAUDE_CONFIG_DIR` and Anthropic credentials for Claude) without crossing into other providers. Agent commands can use a shared issue PTY when no provider secret environment variable is present; secret-backed turns use a sanitized subprocess because a PTY can echo command text into its log. The terminal remains reusable by the UI. Windows PTYs remain unavailable until a ConPTY adapter exists. This is a runtime-boundary repair, not managed account selection.

## Behavioral verification and limits

- `go test ./...` and `go build -o orchestrad ./cmd/orchestrad/` passed in `apps/backend`. Setup and device-login endpoints are in the protected auth matrix. The API tests check response structure, prevent unsupported providers from reporting signed-in, and reject unknown login IDs. The device-login manager has cancellation-state and cross-platform fake app-server protocol tests. No user account was signed in during this verification.
- Focused `internal/agents` tests pass for credential-home scoping; the PTY command isolation test requires bash and is skipped on Windows. The Windows PTY behavior is represented by backend capability discovery and the copy-and-run UI test; a real Windows interactive terminal cannot be tested because it is not implemented.
- `npm run typecheck`, all desktop Vitest tests (774 passed, 2 skipped), `npm run lint` (warnings only), and `npm run build` passed. The focused tests exercise sign-in terminal routing, disabled launch for missing CLI, in-panel device-code presentation and cancellation, roster navigation, backend-profile changes, and cached errors. An asynchronous API Docs loading test and its effect-state warning were repaired during full-suite verification.
- The running preview showed the roster opening above the status bar with all four providers and both source rows fitting at 1280×800. Its backend connection returned HTTP 401 from an invalid preview token, so authenticated setup and usage were not visually verified there. A local `codex login status` exited 0; that establishes only this host's CLI response.
- Managed Codex add/select/reauth/remove, credential isolation, run/native-session binding, and selected-account quota attribution were added in [the follow-up slice](./ade-managed-accounts-2026-10-05.md). Real two-account E2E sign-in remains unverified. Managed Claude, OpenCode, Antigravity, and 8gent accounts remain unavailable because account isolation has not been validated; their authentication cannot be promoted to verified from a catalog or installation check. These remaining gates in [the plan](../superpowers/plans/ade-2026-10-05/harness-onboarding-usage-parity.md) are still required for full Orca parity.
