## Orchestra evidence and model

The existing GitHub [`GetReviewSnapshot`](../../apps/backend/internal/utils/github/review_snapshot.go) reads the pull request, fetches a diff between immutable base/head SHAs, then reads the PR again and rejects changed base/head/state/draft or an unexpected PR number. The existing `GET /api/v1/projects/{project_id}/github/pulls/{number}/snapshot` exposes this snapshot. It is GitHub-specific and it does not execute an agent reviewer.

`internal/reviewgate` persists SQLite review attempts, approval receipts, and merge-completion receipts. Attempts bind the exact local project/task, canonical `owner/repo`, PR URL/number, full head SHA, reviewer provider/profile, reviewer run/session IDs, and a fingerprint of the local task context. Clean evidence reaches `awaiting_human_approval`; approval records a receipt but leaves the task in Review. Findings return only the task state to Todo and replace feedback while preserving its plan, PR link, branch, and working-copy metadata. The changed fingerprint invalidates prior plan approval, so the task needs a newly recorded and approved plan before execution. A task reaches Done only through the separate completion operation after a fresh snapshot proves that the same approved PR head merged.

`internal/reviewpipeline` is wired into the API/control path. A review request verifies the exact task and GitHub PR, checks that it is settled, fetches the current immutable PR snapshot before admission, persists the attempt, and returns immediately. Its worker has a bounded process lifetime independent of the HTTP request. It loads the exact task context, sends the immutable diff and task plan/acceptance/feedback to the provider, supplies no native tools, MCP tools, resources, or custom agent selection, and requires a structured final decision. It fetches the PR and task context again before settling the result. Duplicate request UUIDs observe the existing attempt instead of launching another turn. Startup marks unfinished attempts interrupted. Approval and completion recheck the exact current PR/head and task fingerprint. Stored observations explicitly report that remote freshness has not been checked.

The current selectable reviewer is limited to the provider-default role, identified as `provider-default`; Orchestra does not claim that a custom native primary agent was applied. The capability inventory reports a provider as available only when its exact configured command has a reviewed read-only stage adapter and the executable is present on PATH. This does not test provider authentication. The active registry currently supports reviewed stage adapters for Codex and Claude, subject to those checks. Gemini is removed from active reviewer selection; Antigravity, OpenCode, and 8gent remain unavailable until a read-only stage is verified. Unsupported providers fail before attempt admission. The stage API forces local runtime and plan-only mode and removes tool/resource executors. These controls are not evidence of a live provider-authenticated review.

Review remains GitHub-only. Other PR hosts need an exact native repository identity, immutable head snapshot, and current-head revalidation before they can be enabled.
