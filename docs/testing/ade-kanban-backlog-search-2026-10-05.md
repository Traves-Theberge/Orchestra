## Orchestra investigation and implementation

In `KanbanBoard.tsx`, a card was visually placed in a lane with case-insensitive state matching, but drop dispatch used an exact-case reverse state map. A lower-case `backlog` item therefore rendered in Backlog and could not resolve its source lane on drop. Drag start passed the shared action reference (which falls back through `identifier`, `issue_identifier`, `issue_id`, and `id`), while drop lookup omitted the latter local-ID fallbacks. These two mismatches could silently ignore a Backlog→Todo drop. The current path normalizes state and uses the same identity resolver on both sides. Drag payload keys are now lowercase custom MIME types.

Backlog→Todo still checks trimmed title, description, assignee, and project before calling the existing `onIssueUpdate(identifier, { state: 'Todo' })`. The API transition guard has the same four required fields. This is a state update, not a queue receipt or evidence of agent execution. A read-only backend trace confirmed that the API validates the transition and refreshes orchestration state; any later dispatch is a separate lifecycle event. The new native fixture uses a human-assigned identity that is not a configured worker and verifies the item remains outside worker execution.

## Native result

The updated disposable backend includes the worker-allowlist fix. The smoke creates its project and issue in a temporary profile, sets `ORCHESTRA_TRACKER_WORKER_ASSIGNEE_IDS=agent-fixture-codex`, and verifies the fixture reports `assigned_to_worker: false`, a `person-smoke-*` assignee, and no hosted task source. Search by the exact task identifier succeeded in the real Electron renderer. The pointer hit-test also confirmed the measured target is inside `kanban-column-todo`.

No drag is counted as passed. Electron `webContents.sendInputEvent` produced one browser `dragstart`, but its injected moves exposed `MouseEvent.buttons === 0`; Chromium emitted no `dragenter`, `dragover`, or `drop` even though `document.elementFromPoint` resolved to the Todo column. The installed Orca computer-use driver enumerated the exact visible Electron window by PID, but its native `computer drag` operation timed out at 30 seconds before a post-action state could be read. In every captured failure screenshot the fixture remained in Backlog. Because the API state stayed Backlog and the human assignee remained outside the configured worker allowlist, these attempts did not dispatch an agent. The pointer audit therefore remains an explicit driver limitation, not evidence of a broken application drop handler or of a successful native drag.

The helper retains strict post-drop assertions: it must observe the card leave Backlog, browser drag/drop events, persisted `Todo`, `assigned_to_worker: false`, and no exact fixture identity in `running[]` or `retrying[]`. No DOM-created `DragEvent` is used as a substitute for native input.
