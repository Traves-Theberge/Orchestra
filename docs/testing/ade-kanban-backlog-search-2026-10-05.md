## Orchestra investigation and implementation

In `KanbanBoard.tsx`, a card was visually placed in a lane with case-insensitive state matching, but drop dispatch used an exact-case reverse state map. A lower-case `backlog` item therefore rendered in Backlog and could not resolve its source lane on drop. Drag start passed the shared action reference (which falls back through `identifier`, `issue_identifier`, `issue_id`, and `id`), while drop lookup omitted the latter local-ID fallbacks. These two mismatches could silently ignore a Backlog→Todo drop. The current path normalizes state and uses the same identity resolver on both sides. Drag payload keys are now lowercase custom MIME types.

Backlog→Todo still checks trimmed title, description, assignee, and project before calling the existing `onIssueUpdate(identifier, { state: 'Todo' })`. The API transition guard has the same four required fields. This is a state update, not a queue receipt or evidence of agent execution. A read-only backend trace confirmed that the API validates the transition and refreshes orchestration state; any later dispatch is a separate lifecycle event. The new native fixture uses a human-assigned identity that is not a configured worker and verifies the item remains outside worker execution.
