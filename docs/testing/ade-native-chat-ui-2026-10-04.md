## Orchestra adaptation

`WorkspaceChat.tsx` remains mounted per backend/project in the existing workspace layout, preserving conversation-specific drafts across workspace switches. Kanban stays the task overview. New UI consumes the workspace chat service's persisted events and runtime requests rather than interpreting terminal transcripts.

- Assistant deltas render during unfinished turns; completed turns use persisted final messages to avoid duplicate text.
- Command/file/tool/reasoning activity, command output, plans and provider errors are expandable observations.
- Approval actions are allow once or deny, scoped to project, conversation and exact request ID. Buttons disable immediately during a reply; uncertain outcomes do not trigger retries.
- Provider questions retain typed question IDs, options and custom answers. Unsupported formats do not fabricate an answer.
- Native continuity, provider thread, requested model, observed effective model, approval policy and sandbox are separate labels. Missing effective state stays unknown.
- Provider token usage displays observed input/output/cache/total fields; absent usage remains unobserved. No token-cost estimate is fabricated.
- Failed message delivery retains the draft and blocks a new send for that conversation. Subsequent observation of the same client-message ID reconciles its acceptance. Polling never resends a mutation.
- Stop invokes only the chat-turn interrupt endpoint, never task reset or worktree deletion.

The native composer now loads the actual provider model catalog through the project-scoped backend. Provider-default/current-session remains the initial selection, with no model override sent. Explicit choices submit the catalog's `model` slug, not opaque IDs, as next-turn `requested_model`. Hidden models are omitted. Backend/profile/project/provider/conversation changes invalidate stale catalogs; ownership mismatch or read failure cannot introduce choices, erase drafts, or fabricate entitlement. Requested and provider-observed models remain distinct labels.

Deliberate deviations: snapshots poll every second during a running turn rather than using T3's reactive transport. Events are a compact expandable activity view rather than full T3 timeline parity. No hardcoded model list, editable policy control, or arbitrary model textbox was introduced. Native provider support is backend reported; other providers may still use explicitly labeled transcript replay and their model picker is unavailable. Attachments, rich artifacts, editable plan modes, steer/queue controls and native Claude parity remain separate work.

## Renderer reload recovery

At the same pinned T3 revision, inspected composerDraftStore.ts persistence, deferred-write/unload flushing, app-facing scope keys, normalization and persisted draft selection. T3 retains user content and promoting draft identities while excluding runtime-only data. At the same pinned Orca revision, inspected complete use-native-chat-draft.ts and native-chat-draft-cache.ts: stable pane keys own drafts across composer unmounts, empty drafts are dropped, and the cache is bounded and in memory. Orca's pane cache alone does not establish renderer-reload durability.

Orchestra adapts these patterns with tab-scoped sessionStorage, SHA-256 keys derived from backend URL/account token/project, and per-conversation draft ownership. Raw configured tokens and URLs are not written into storage keys or receipt values. Only user drafts, selected conversation/provider and recovery identities are stored; provider transcripts, account settings and model catalogs remain outside this receipt. Empty drafts are omitted. Credential changes or project/backend changes remount the scoped owner and use a different storage key. Tab closure is deliberately outside sessionStorage's persistence lifetime.

Draft edits write synchronously after storage initialization. Create/message/request identities are written before their mutation boundary. Restored creation, message or reply uncertainty is blocked and reconciles through scoped reads; there is no automatic mutation replay. Explicit creation recovery retains the exact client session ID and leaves the message unsent. A single unresolved creation/message prevents a second dispatch from replacing its recovery identity. An accepted earlier message cannot erase a newer correction draft. Storage/crypto failure shows a visible keep-tab-open warning and retains in-memory operation; no durable recovery is claimed in that case.

Verification: 36 focused chat/layout tests passed, including renderer remount restore, backend/account/project isolation, absence of configured credentials in storage, uncertain creation reload plus explicit same-ID recovery without send, uncertain message reload plus observed receipt reconciliation, and correction draft preservation. Scoped ESLint and desktop typecheck passed. These are renderer tests, not a live reload/provider E2E certification. No account provider execution or provider settings writes were performed in this package.

## Desktop relaunch durability

Orchestra now follows the previously inspected pinned T3 app-facing persistent draft pattern for Electron app relaunches: desktop-bridge presence selects profile localStorage, using the unchanged SHA-256 backend/account/project scope key. Browser-only sessions remain sessionStorage scoped. A valid existing same-key tab receipt migrates to the profile store; it is removed from tab storage only after the durable write succeeds, preventing stale copies from superseding later drafts. Failed migration keeps the old tab receipt and reports failed writes to the existing visible warning path. User draft text and recovery identities are retained; configured credentials remain memory-only.
