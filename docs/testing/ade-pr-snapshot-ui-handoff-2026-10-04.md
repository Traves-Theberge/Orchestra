The inspected Orca merge action does not establish a head-SHA precondition. Neither reference application was run; no source was copied.

Orchestra independently combines those identity/error patterns with [GitHub's commit comparison endpoint](https://docs.github.com/en/rest/commits/commits#compare-two-commits), which accepts immutable SHA comparisons and diff media. A new project-scoped `/github/pulls/{number}/snapshot` fetches PR metadata, a base/head-SHA-pinned comparison diff, and metadata again. Changed head/base/state/draft or missing identity fails visibly. Requests have a 30-second total deadline and an 8 MiB response limit. This is an API snapshot, not a durable review approval/check record.

The review panel resets across project/PR/backend identity, ignores obsolete asynchronous loads, shows load/mutation errors and a refresh action, and disables mutations while loading, on failure, or for a closed/merged/draft snapshot. Merge sends the displayed head SHA through the [strict backend guard](ade-pr-reviewed-head-merge-handoff-2026-10-04.md). Confirmed success updates the panel to merged; it does not advance the task to Done or infer hosted checks/approval policy. The parent PR list still requires its normal refresh.

New utility fixtures test immutable comparison paths, stable snapshots, changed head/base, wrong identity, missing SHA and failed comparison. Production-router fixtures test the snapshot response and changed-head conflict against disposable SQLite and local HTTP. Renderer tests cover displayed-SHA submission, confirmed merged status, visible failed loading/merge, and late prior-PR results. A client test verifies the actual merge JSON carries `expected_head_sha`.

Limitations: hosted review submissions still lack commit anchoring; review/check requirements are not independently reconciled. Project repository configuration can change between loading and merging; canonical repository revision fencing remains open. Large/binary diff completeness and fork behavior need hosted canaries. Lost merge responses require refresh/reconciliation, not automatic replay. No real GitHub merge or provider call was made.
