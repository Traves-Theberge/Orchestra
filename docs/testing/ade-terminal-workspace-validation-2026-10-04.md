# Terminal workspace validation handoff — 2026-10-04

Scoped implementation of the invalid-checkout finding in the [terminal audit](ade-terminal-workspace-reference-2026-10-04.md), following the [pinned source registry](../superpowers/plans/ade-2026-10-03/reference-patterns.md). No reference application runtime was inspected and no reference source was copied.

References inspected before implementation:

- T3 Code `737993303d36e10674c54b95e5bd3826682c99c7`: [terminal Manager.ts](https://github.com/pingdotgg/t3code/blob/737993303d36e10674c54b95e5bd3826682c99c7/apps/server/src/terminal/Manager.ts) and [Manager.test.ts](https://github.com/pingdotgg/t3code/blob/737993303d36e10674c54b95e5bd3826682c99c7/apps/server/src/terminal/Manager.test.ts). The manager checks the requested cwd with filesystem stat and reports distinct missing, non-directory and stat errors before starting a session. Tests and manager interface describe thread-scoped lifecycle behavior; they do not establish Orchestra runtime behavior.
- Orca `3284b4c70c901402831bb4ccc5576ea083d2e5ae`: [terminal-host-session-create.ts](https://github.com/stablyai/orca/blob/3284b4c70c901402831bb4ccc5576ea083d2e5ae/src/main/daemon/terminal-host-session-create.ts) and [terminal-create idempotency tests](https://github.com/stablyai/orca/blob/3284b4c70c901402831bb4ccc5576ea083d2e5ae/src/main/runtime/orca-runtime-terminal-create-idempotency.test.ts). The daemon probes requested cwd readability before spawning because shell fallback can obscure the request. Tests reject wrong-worktree identity and unavailable inventory without creating another terminal. Both references have relevant requested-workspace failure patterns.

Orchestra adaptation: [terminal.go](../../apps/backend/internal/api/terminal.go) rejects unknown requested projects with 404, unavailable project lookup with 503, invalid absolute-directory requests with 400, and paths outside the same `ProjectRoots` policy used by workspace routes with 403. Checks occur before WebSocket upgrade. Registered project paths are checked independently so a valid cwd cannot mask an unauthorized project. Explicit valid child checkout paths retain precedence; no project containment rule was added beyond the shared configured root policy. The unscoped default and existing issue-worktree discovery remain intact.

Deliberate differences: this fix adds HTTP boundary errors, rather than a new terminal lifecycle or ownership contract. Orchestra uses its existing Go filesystem guard and project registry, and retains its current session IDs and optional issue-worktree discovery. It does not adopt Orca mutation reconciliation or T3 thread identities. Existing session reuse by caller-supplied ID remains a separate audit gap.

Behavioral verification on Windows: `cd apps/backend; go test ./internal/api -run 'TestTerminalWorkspace|TestTerminalProject|TestIsTerminalAuthorized' -count=1` passed. New [terminal_workspace_test.go](../../apps/backend/internal/api/terminal_workspace_test.go) exercises actual existing/missing/relative/file/outside directories; unknown projects with and without valid overrides; unavailable lookup; unauthorized registered projects; exact allowed child overrides; unscoped defaults; and existing issue-worktree selection even when the primary fixture directory is absent. A nil terminal manager and non-upgrade requests establish that rejection occurs before manager invocation. Valid paths reach the actual WebSocket handshake rejection. Both changed Go files are gofmt-clean.

Evidence level: HTTP handler and filesystem boundary verified. No shell was spawned. This is not terminal E2E, native Windows PTY, desktop rendering, process isolation, or reconnect proof. No global settings or provider authentication changed.
