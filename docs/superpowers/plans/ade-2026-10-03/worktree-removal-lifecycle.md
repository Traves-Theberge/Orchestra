- T3 Code source revision: [`pingdotgg/t3code` `737993303d36e10674c54b95e5bd3826682c99c7`](https://github.com/pingdotgg/t3code/tree/737993303d36e10674c54b95e5bd3826682c99c7). The pinned [`apps/server/src/mcp/WorktreeMcpService.ts`](https://github.com/pingdotgg/t3code/blob/737993303d36e10674c54b95e5bd3826682c99c7/apps/server/src/mcp/WorktreeMcpService.ts) covers worktree creation and handoff, not a user-facing worktree-removal operation. For failed creation it rolls back the newly created checkout with force and deletes the freshly created branch only after checkout removal succeeds. No equivalent user-removal surface was found in the inspected T3 source slice.

The sources establish patterns, not Orchestra runtime reliability. Their worktree deletion defaults, branch policy, and recovery cleanup differ intentionally from this package.

## Orchestra contract and adaptation

Each non-primary workspace card offers **Workspace actions → Remove worktree**. Confirmation shows the exact branch and canonical path, states that the checkout directory is removed, and says the local branch and agent conversation history remain. Registered/root and main worktrees have no removal control. Locked or prunable entries are unavailable.

The backend resolves the workspace ID from the registered project's live Git worktree list, persists a request-specific receipt before preflight/effect, and re-resolves project root, workspace membership, canonical checkout path, branch, and HEAD immediately before the Git mutation. It refuses tracked, untracked, ignored, or submodule changes. It invokes `git worktree remove -- <path>` without force, never deletes a branch, never recursively deletes a path, and never mutates provider transcripts. A partial unique index fences one pending/unknown removal per project/workspace across backend processes. Startup converts interrupted pending work to unknown; the same request ID is used for receipt lookup and recovery, and a new request is not allowed to replay an unknown effect.

The admission fence covers the selected canonical directory in the PTY manager, blocks project task admission/retries while removal is unresolved, and blocks native session dispatch for the exact project/workspace/path. Unknown ownership or dispatch state blocks removal. Runtime task counts in the card alone do not decide safety. Session archive is a separate metadata-only lifecycle operation: archive hides the session from default lists while preserving provider identity and history. The project tree exposes per-conversation archive/restore controls and a DB-only archived-history viewer; after checkout removal, archived history remains readable while restore stays unavailable until the exact workspace ID/path is live again. Removing a worktree does not archive or delete conversations implicitly. Session stop/delete and broad terminal cleanup remain unavailable unless the backend observes and supports those capabilities.

The deliberate Orca deviations are: preserve every branch, reject any dirty or ignored checkout even if Git might otherwise accept a cleanup option, avoid recursive host cleanup after Git, and require durable request identity. The T3 handoff/rollback is not reused for existing resources; only its identity recheck and ordered-effect discipline are adapted.

## Behavioral verification

Independent Orchestra verification uses disposable Git repositories and temporary SQLite databases only:

- `apps/backend/internal/workspacelifecycle/service_test.go` exercises clean removal, branch/root retention, request replay and identity conflict, tracked/untracked/ignored-file refusal, protected primary checkout, busy admission, identity drift, restart-to-unknown, same-receipt reconciliation, and no replay.
- `apps/backend/internal/api/project_worktree_removals_test.go` exercises the authenticated-router lifecycle against real Git: primary refusal, dirty checkout preservation, clean removal, branch retention, same-ID replay, and receipt lookup.
- `apps/backend/internal/terminal/removal_test.go` verifies active PTY blocking and that a new PTY cannot enter the fenced directory.
- `apps/desktop/src/features/projects/ProjectWorkspaceTree.test.tsx` verifies that primary cards omit the action, the child-card menu and exact-path confirmation render, success refreshes the observed worktree list, lost replies reconcile through the same request receipt, and unknown receipts disable a second DELETE.
- The same tree suite verifies per-session archive as a separate action and archived transcript reads using the retained project/workspace/path identity after the checkout disappears.
- Focused checks run for this package: `go test ./internal/workspacelifecycle ./internal/terminal ./internal/orchestrator`; desktop `npm run typecheck`; and `npm run test -- --run src/features/projects/ProjectWorkspaceTree.test.tsx`. The focused API lifecycle/auth route checks are `go test ./internal/api -run 'TestProjectWorktreeRemovalHTTPKeepsBranchAndRejectsDirtyCheckout|TestAuthMatrixCoversAllRoutes|TestAuthMatrixProtectedRoutesRequireBearer' -count=1`.

The app's Windows PTY implementation is unavailable, so the PTY-manager runtime path cannot be exercised on this host; its admission semantics are tested directly. Native browser smoke remains separately responsible for verifying the actual UI network boundary and uncertain-response path.
