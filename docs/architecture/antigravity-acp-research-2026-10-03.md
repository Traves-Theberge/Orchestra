# Antigravity ACP integration research

Research date: 2026-10-03. **Evaluate Google's official ACP runtime as the preferred candidate for Orchestra's full native chat.** This recommendation follows the required pinned T3 implementation and its negotiated approval/session boundary. It is an architectural inference from source, not an authenticated runtime result. Keep the CLI NDJSON preparation unwired until transport selection is proven; CLI control replies are documented unsupported.

No runtime was downloaded, installed, launched, or authenticated during this research. No user configuration was written. The installed `agy` CLI 1.2.16 is a different interface from the ACP release below.

## Authentication and capabilities must be demonstrated

Current [Google IDE-extension documentation](https://antigravity.google/docs/ide/extensions/) describes a unified account authentication/entitlement system across extensions, CLI and desktop. The pinned [T3 guide](https://github.com/pingdotgg/t3code/blob/737993303d36e10674c54b95e5bd3826682c99c7/docs/user/providers-antigravity.md) requires sign-in into T3's isolated ACP profile. These observations do not establish automatic reuse of existing CLI credential files. Use the official negotiated login flow in an Orchestra-owned profile and verify entitlement/model access there; never extract or copy account tokens to bridge interfaces.

Source indicates richer session/model/approval/chat capabilities than CLI NDJSON. T3 source supports image, text-resource and selected audio prompt routes; its pinned user guide describes narrower attachment behavior. That discrepancy reinforces using negotiated capabilities and actual traces. Start with text; gate every additional input type on observed runtime acceptance. Do not enable rewind, arbitrary steering, individually controlled native children, or full sandbox guarantees by inference.

## Concrete execution sequence

1. **Prepare a transport fixture first.** Typed JSON-RPC request IDs, session updates, offered permission IDs, prompt terminal reasons, bounded I/O and unknown-method/errors. Record a dispatch receipt before writing. Simulate missing/late replies, reordered completion, invalid options, process loss and cancel timeout without model inference.
2. **Acquire an isolated runtime.** Pin manifest/release and archive hash; inspect executable/helper pairing. Put installation and profile in explicit Orchestra-owned directories, with HOME/USERPROFILE/config/environment isolated in probes. No global config edits. Recheck current provider terms before any bundled distribution.
3. **Prove unauthenticated discovery.** Initialize only in a disposable workspace/profile; save redacted version/capability/auth-method traces and timing. Verify no workspace writes. Binary presence must not yield authenticated/ready.
4. **Perform explicit account setup.** Negotiate the official login method and observe successful session/model discovery. Record account-instance association without persisting secrets in task artifacts. Confirm whether access differs from CLI.
5. **Prove one harmless text turn and resume.** Persist session/task/attempt mapping, stream ordered messages/tools, await prompt terminal reason, restart and resume the exact session. Reapply explicit model/mode and verify returned values. Do not use latest-session selection across tasks.
6. **Prove interactive controls.** Observe a harmless approval request; exercise allow-once/deny/cancel and a fixed-choice question. Test stale responses, reconnect while pending, cancel settlement and forced process loss. Verify children actually stop or expose reduced guarantees.
7. **Prove workspace/config isolation.** Two concurrent sessions with separate worktrees/profiles/configurations; test escaping links, resource paths and unsupported capability failure. Persist effective config and provenance through restart.
8. **Integrate only after those receipts.** Use one shared backend session/control service for native chat and Kanban task execution, then earn independent lifecycle/check/PR revision evidence. Full ADE orchestration remains Orchestra-owned.

The [CLI protocol handoff](../testing/antigravity-protocol-handoff-2026-10-03.md) provides useful typed identity and terminal-classification preparation, but is not an ACP implementation. None of the real-provider gates above is complete.
